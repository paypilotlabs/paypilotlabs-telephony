# Review: PayPilotLabs Telephony (2026-11-11)

Scope: everything since the first commit (`9738496`), plus the app code those commits ship, plus how the sibling repos depend on this app. Read only; no code changed.

PayPilotLabs changes since the first commit are small: repo files (README, NOTICE, SECURITY, CI, templates), `telephony/brand.py`, logo files, and four lines in `telephony/hooks.py`. No doctypes, fields, functions or routes were removed, so there are no dead references. `check_independence.py`: OK (run 2026-11-11).

Most bugs below are upstream (they were in `frappe/telephony` at `94475775`). They matter more here because PayPilotLabs Helpdesk lets logged-in portal customers (website users) call any `telephony.*` method: `paypilotlabs-helpdesk/helpdesk/auth.py:93`.

## 4. Naming plan

### Option A: metadata only (recommended)

Bench app name, Python package and API paths stay `telephony`. Changes:

1. `pyproject.toml`: PayPilotLabs description, Frappe kept as author, PayPilotLabs added as maintainer, `[project.urls]` added.
2. `hooks.py`: `app_description` from `brand.py`.
3. `tp_otp_settings.json:36`: "your configured outgoing Email Account".
4. `tp_twilio_settings.py`: new Twilio resources are named `PayPilotLabs Telephony`; lookup also accepts the legacy `Frappe Telephony` name.
5. `brand.py`: real support email (needs your address).

Optional add-on A2: rename the `FTelephony` module (medium risk, needs a migration patch). Not recommended now: only admins see it.

Risk: low. No other repo changes. No customer action.

### Option B: full rename to `paypilotlabs_telephony`

Everything in A, plus:

- This repo: move `telephony/` to `paypilotlabs_telephony/`; update `pyproject.toml` name, `hooks.py` (`app_name`, all `telephony.` paths), `brand.py` asset paths, `.github/scripts/check_independence.py` (`PACKAGE`), CI compile path, and these files: `api.py`, `email_otp.py`, `otp.py`, `exotel/handler.py`, `twilio/api.py`, `twilio/sms.py`, `twilio/test_api.py`, `twilio/twilio_handler.py`, `tp_otp_settings.py`, `test_tp_otp_settings.py`, `test_tp_otp.py`, `tp_twilio_settings.py`.
- paypilotlabs-helpdesk: `helpdesk/hooks.py` (`required_apps`), `helpdesk/auth.py:93`, `helpdesk/patches/add_telephony_app.py`, `desk/src/stores/telephony.ts`, `desk/src/components/Settings/Telephony/{Telephony,ExotelSettings,TwilioSettings}.vue`, `desk/src/components/telephony/{CallUI,ExotelCallUI,TwilioCallUI}.vue`, `desk/src/pages/call-logs/{CallLogModal,CallLogDetailModal}.vue`.
- Existing sites: `Installed Application` and `Module Def.app_name` rows must be migrated, or the app reinstalled (losing nothing only if done carefully).
- Old API paths: webhooks are POSTs signed against the exact URL, so an HTTP redirect cannot keep them working. It would need a `telephony` compatibility package that re-exports the old whitelisted functions, shipped in the same distribution.
- Customers: re-save TP Twilio Settings (and the code must also update the existing TwiML app's voice URL; today it does not), and update the Exotel webhook URL by hand.

Risk: high. Breaks live calls on any site that already uses Twilio or Exotel until each step is done.

### Recommendation

Option A, plus bug fixes 1 to 7. Option B adds risk and customer work for a name only admins and developers see.
